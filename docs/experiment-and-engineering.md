# 实验范式与工程实现

## 比较什么

比较标签范式时，尽量对齐模型骨干、输入处理、校准预算、训练预算和在线后处理。单标签条件使用互斥类别，多标签条件允许多个运动单元同时激活。传统线性基线属于研究论证方向，不在此声明已有完整对照结果。

## 将实验规则落成软件

| 问题 | 实现 |
|---|---|
| 各类出现次数均衡且相邻不重复 | 固定随机种子、回溯搜索与失败状态缓存 |
| 实验阶段和暂停恢复一致 | 显式状态机及阶段事件记录 |
| 训练条件可比 | 对照已保存配置核验关键训练与预处理设置 |
| MVC缺失或通道不符 | 共用读取校验，拒绝非有限、零值或不匹配输入 |
| 原始数据与试次对应 | CSV配套样本元信息、session与trial标识 |
| 提示与预测时序可追溯 | 同时保存UTC和单调时钟事件 |
| 界面流畅但记录不能静默漏存 | 显示与记录分离、有界队列和独占写入 |
| 串口输入不完整或中断 | 明确切帧、畸形输入和超时处理 |

## 功能评价方向

围绕BBT、随机抓取、SHAP-12、可选Block Turn和主观负荷研究任务流程、计时与评分定义。其中SHAP-12为手功能评估任务，与模型可解释性SHAP不同。当前展示方案研究、调度和接口工作，正式功能性比较结果另行验证。

## 软件验证与真实设备验证

已开展模拟输入下的计划、记录、标注、训练和模型重载试跑，并定位修复排程与归一化不一致问题。视频记录本人肌电采集、模型训练、加载机械手后的在线动作验证；软件试跑、真机动作验证和正式功能评价分别记录。
